Low-Level Design (LLD)
LLD is the highly detailed design that lives inside each component outlined in the HLD. It moves from the abstract blueprint to the concrete implementation details a developer needs to start coding.

Definition: The LLD details the component logic, often defining the internal data structures, classes, modules, functions, and database schemas. It specifies the logic required to implement a specific system feature.
The Engineer's Job: The engineer/contractor uses the blueprints but also needs the specific details to execute the plan. They decide:
How many electrical sockets go in the kitchen.
The exact specification for the kitchen sink plumbing (e.g., pipe size and material).
The specific SQL commands or object-relational mapping (ORM) required for a function.
System Example: For the social media platform's User Service (a component from the HLD), the LLD specifies:
The User class should have private fields like userId (UUID), username, and passwordHash.
The registerUser(details) function performs input validation, encrypts the password, and calls a specific SQL stored procedure.
The exact schema for the users table (e.g., username column must be unique and indexed).

1. All OOPS concepts - what are - Classes, Objects, inheritance, Abstraction, polymorphism 
2. SOLID principles
3. Design patterns - Factory, Abstract Factory, Singleton and observer, builder, decorator, facade, adaptor.
4. Drawing class diagrams properly. ( As a , Has a ). UML conventions
5. Sequence diagrams, Usecase diagrams
6. Test cases - How to design edge cases.
7. Multi threading, thread safety.
